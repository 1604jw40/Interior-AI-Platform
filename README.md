# Interior AI Platform

실내 이미지에서 객체를 찾고, 가구의 3D 표현을 생성해 Unity에서 배치하는 실험용 인테리어 플랫폼입니다.

현재 저장소는 기존 개발 코드를 보존한 프로토타입입니다. 아래 설명은 저장소의 소스 구성을 기준으로 하며, 전체 서비스를 새 환경에서 실행하거나 성능을 재측정한 결과는 아닙니다.

## 구성과 데이터 흐름

1. Unity 클라이언트가 C++ 서버에 방 분석을 요청합니다.
2. `ai-perception`이 입력 이미지에서 RF-DETR로 객체를 찾고, 객체별 이미지와 좌표·크기 추정값을 만듭니다.
3. C++ 서버가 객체별 3D 재구성을 요청합니다.
4. `ai-reconstruction`이 SAM으로 객체 영역을 처리하고 LGM 추론으로 PLY를 생성합니다.
5. Unity가 HTTP로 PLY를 받아 장면에 배치합니다.

Unity와 C++·Python 서비스 간 메시지는 ZeroMQ와 FlatBuffers를 사용합니다. 현재 코드의 위치·크기 추정은 카메라 높이·시야각·하향각을 가정한 기하 계산이며, 학습된 깊이 모델의 정확도를 검증한 결과가 아닙니다.

## 저장소 구조

| 경로 | 역할 |
| --- | --- |
| `InteriorUnity/` | Unity 장면, 네트워크 클라이언트, PLY 로더·렌더링 |
| `services/logic-cpp/` | C++17 기반 서비스 요청·응답 조정 |
| `services/ai-perception/` | RF-DETR 객체 탐지와 좌표·크기 추정 |
| `services/ai-reconstruction/` | SAM 전처리, LGM 실행, 생성 에셋 HTTP 제공 |
| `services/matching-engine/` | 매칭 서비스 자리표시자. 현재 Dockerfile은 더미 메시지만 출력 |
| `infrastructure/` | PostgreSQL 및 상품 DB 관련 구성 |
| `shared/schema/` | FlatBuffers 스키마와 언어별 생성 코드 |

## 개발 환경과 준비 사항

- Unity 프로젝트 기록: **6000.4.0f1**
- Docker와 Compose
- GPU 경로를 사용할 경우 호환되는 NVIDIA 드라이버·컨테이너 런타임
- 각 Python 서비스의 `requirements.txt`
- RF-DETR·SAM·LGM의 모델 파일과 해당 모델의 이용 조건 확인

대용량 모델과 입력 이미지·생성 PLY는 코드와 분리해 준비합니다. 현재 코드가 참조하는 대표 파일은 `shared/models/test_room.jpg`, `best.pt`, `model.safetensors`입니다. 모델 다운로드·버전 고정·무결성 검증 절차는 아직 통합되어 있지 않습니다.

## 재실행 전 확인

이 저장소는 즉시 실행 가능한 배포 패키지로 검증되지 않았습니다. 다음 항목을 먼저 정리해야 합니다.

- `services/ai-reconstruction/lgm_core`는 Git 하위 모듈 항목이지만 루트 `.gitmodules`가 없어 원본 LGM 소스 연결을 확인해야 합니다.
- Compose가 참조하는 `infrastructure/init_db.sql`과 매칭 서비스 소스 등 일부 경로가 현재 저장소에서 제공되지 않습니다.
- Unity와 재구성 서비스에 개발 당시 서버 주소가 들어 있습니다. 현재 실행 환경에 맞춰 설정을 분리해야 합니다.
- Compose의 GPU 예약과 Python 패키지 구성이 실제 환경에 맞는지 확인해야 합니다.
- `ai-perception`의 일부 3D 생성 경로는 샘플·자리표시자 처리입니다. 최종 3D 재구성과 동일한 기능으로 해석하지 않습니다.
- 탐지·재구성·Unity 배치를 잇는 전체 실행과 오류 복구, 지연시간은 별도로 검증해야 합니다.

### 로컬 비밀정보 설정

루트의 `.env.example`을 `.env`로 복사하고 `POSTGRES_PASSWORD`에 로컬 전용 비밀번호를 입력합니다. Compose는 값이 없거나 비어 있으면 실행 전에 오류를 반환합니다. 데이터베이스와 매칭 서비스는 같은 변수를 참조합니다. `.env`는 Git 제외 대상이며 실제 값을 문서나 커밋에 적지 않습니다.

`OPENAI_API_KEY`는 현재 더미 매칭 서비스의 선택 변수입니다. 현재 저장소에는 이 키를 사용하는 완성된 매칭 구현이 없습니다.

기존 PostgreSQL 데이터 디렉터리에서는 환경변수를 바꿔도 저장된 계정 비밀번호가 자동으로 바뀌지 않습니다. 이 변경은 기존 DB·계정이나 운영 설정을 수정하지 않습니다. 기존 인스턴스를 재사용하려면 데이터를 보존한 상태에서 계정 설정을 별도로 확인해야 합니다.

별도 상품 DB는 [`infrastructure/product_db/README.md`](infrastructure/product_db/README.md)를 참고합니다.

필요한 설정과 모델을 준비한 뒤 로컬에서 Compose 구성을 검사할 수 있습니다.

```bash
docker compose config --quiet
```

구성 문법 검사는 모델 로딩·GPU 호환성·서비스 통신 성공을 보장하지 않습니다. 현재 문서 정비에서는 컨테이너 빌드나 전체 실행을 수행하지 않았습니다.

## 공개 저장소 관리 주의

- 비밀번호, API 키, 인증 파일과 `.env`는 업로드하지 않습니다.
- DB 실행 데이터, WAL, IDE 캐시와 생성 결과는 소스와 분리합니다.
- 기존 이력에 포함된 파일은 `.gitignore`를 추가해도 제거되지 않습니다. 이 저장소의 과거 DB 파일·자격증명 이력은 별도 검토가 필요합니다.
- 실사용 또는 다른 곳에서 재사용한 자격증명이라면 교체가 필요합니다. 문서 수정은 자격증명 교체나 Git 이력 정리를 대신하지 않습니다.
- 모델·외부 라이브러리·상품 정보·이미지의 배포 권한은 각각 확인해야 합니다.
